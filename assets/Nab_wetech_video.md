### **4. WHY SDLC MATTERS (1 minute)**
<!-- **Remember: Quality Gates Story → My Example** -->

Software Development Life Cycle's **quality gates** that save projects.

Think of it like this:
- **Requirements** → Build the RIGHT thing
- **Design** → Catch mistakes BEFORE coding
- **Testing** → Find bugs BEFORE users do
- **Deployment** → Launch reliably
- **Maintenance** → Keep it healthy

Real example: My thesis project - the book rental system.

I followed Software Development Life Cycle: wrote requirements, designed database, built incrementally, tested thoroughly.

Result? 10,000 visits. Score 9.5 out of 10.

### **5. WHAT IF WE SKIP Software Development Life Cycle? (1 minute)**
<!-- **Remember: Real Story from Vietsovpetro** -->

At Vietsovpetro, I directly witnessed the consequences of another team skipping the testing phase. They delivered an important project for all 4,000 users but published it before completing testing and certainly never tested handling 3,000 concurrent requests in a single morning. As a result, the company incurred significant financial losses. One of the reason is, The project owner wanted to rush the deployment out of fear that delaying it would make matters worse, while the team's project manager was overly optimistic about systems

**The lesson?**
- Skip requirements → Build wrong features
- Skip design → Create technical debt
- Skip testing → Users suffer
- Skip security → Data leaks

SDLC is not optional. It's our professional responsibility. It's what separates good software from disasters.
